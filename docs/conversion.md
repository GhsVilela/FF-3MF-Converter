# How conversion works

FF-3MF does not slice. It rewrites the project layer of a 3MF so Flash Studio
opens it with a FlashForge printer, process and filament profile, while keeping
the author's model and print intent.

## 3MF project layout

An Orca-family project is a ZIP containing:

```
[Content_Types].xml
_rels/.rels
3D/3dmodel.model
3D/Objects/*.model
3D/Textures/*
Metadata/project_settings.config
Metadata/model_settings.config
Metadata/custom_gcode_per_layer.xml
Metadata/layer_config_ranges.xml
```

The important files are:

- `project_settings.config` — a flat JSON snapshot of printer, process and
  filament settings.
- `model_settings.config` — object/part overrides, plate assignments and
  per-object extruder metadata.
- `3dmodel.model` and `3D/Objects/*.model` — geometry, materials and painted
  triangle attributes.

## Conversion steps

### 1. Detect the source

The converter checks `Application`, `BambuStudio:3mfVersion`, the presence of
`project_settings.config` or `Slic3r_PE.config`, and the archive entries. A
sliced `.gcode.3mf` is rejected.

### 2. Analyse

The core reads model XML with a streaming scanner and collects:

- Objects, instances, vertices, triangles and units.
- Plate count and object-to-plate membership.
- Painted colour states, painted supports and painted seams.
- Per-object and per-volume extruder values.
- Bounding boxes for bed fit.
- Source filaments that are actually used.

### 3. Build the target configuration

A target template generated by headless OrcaSlicer supplies a complete
`project_settings.config` for the target generation. The converter then:

- Overlays the exact target machine and selected process settings.
- Selects target filament presets by material.
- Expands per-filament arrays to the target slot count.
- Applies the source author's overrides.
- Sets target identity and compatibility metadata.

### 4. Translate author settings

Only settings listed in the source's `different_settings_to_system` are treated
as author overrides. This avoids copying every source default into the target
project.

Kept categories include:

- Layer height and initial layer height.
- Walls, shells, top/bottom layers and line widths.
- Infill density and pattern.
- Supports: type, angle, placement, interface layers and spacing.
- Seam, scarf, brim, skirt, raft and draft shield.
- Ironing, fuzzy skin, spiral vase and gap fill.
- Temperatures, clamped to the target range.
- Per-object overrides from `model_settings.config`.

Dropped categories include:

- Speeds, acceleration and jerk.
- Pressure advance and adaptive pressure advance.
- Retraction, z-hop and wipe tuning.
- Fan curves and chamber control.
- Machine limits and start/end G-code.
- Bambu AMS, camera, calibration and lidar keys.
- Source filament IDs and hardware-specific metadata.

The report lists every decision with a reason.

### 5. Filament mapping and paint

Used source filaments are compacted and mapped to target slots. The paint
bitstream uses the TriangleSelector format shared by PrusaSlicer, Bambu Studio
and OrcaSlicer:

- A leaf encodes a filament state.
- A split node describes a triangle subdivision.
- The hex string is serialized in reverse nibble order.

The converter parses the tree, remaps every leaf, and re-encodes it. It never
performs text replacement on paint strings. Painted supports and seams are
renamed to the Orca attribute names and copied unchanged.

For a single-colour printer, all painted states collapse to slot 1. For a
four-colour printer, up to four used source slots are preserved in order; extra
slots are merged by the selected mapping. If `keepAllColors` is enabled, the
converter keeps one filament slot per used source colour instead. This can
produce more filament slots than the target printer has toolheads, so the report
adds a warning and the mapping must be verified in Flash Studio before slicing.

### 6. Plates and layout

Plates are preserved. For a single-plate project, the converter can centre the
model on the target bed. It never scales automatically. If the model is larger
than the bed, it warns and leaves the decision to the user (or uses the explicit
"scale to fit" option).

### 7. `different_settings_to_system`

This array is essential. It tells Orca/Flash Studio which project values are
overrides rather than system defaults. Its layout is:

```
[0] process overrides
[1..N] filament overrides, one entry per filament
[N+1] printer overrides
```

FF-3MF recomputes it by comparing the final configuration with the target
process, filament and machine baselines. Without this step, settings can be
silently reset when the project is opened or sliced.

### 8. Packaging and validation

The output uses a minimal, valid 3MF package:

- A standard content-types file.
- Root and model relationships.
- Rewritten root and object model XML.
- `project_settings.config` and patched `model_settings.config`.
- Optional custom G-code, layer ranges and thumbnail.
- No stale slice info, plate G-code or source-printer thumbnails.

Before download, the output is reopened and checked for target identity,
filament counts, array lengths, paint ranges and the application stamp.
